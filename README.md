<h1 align="center">CHZZK Archiver</h1>
<p align="center">치지직 방송을 편집용으로 모아두는 개인용 아카이버</p>

편집할 방송을 모으다 보면 영상만 받아선 부족합니다. 어디가 재밌었는지 찾으려면 결국 채팅을 다시 봐야 하니까요. 그래서 영상·채팅·하이라이트 마커를 한 번에 만들도록 묶었습니다. 다시보기가 올라오지 않는 방송도 있어서 라이브 녹화 경로를 따로 두었습니다.

## 하는 일

링크 하나(또는 방송 시작)로 네 가지가 만들어집니다.

- **영상** — 최고 화질(1080p60)
- **채팅 로그** — 전체본과 필터본
- **프리미어 마커 XML** — 채팅이 몰린 구간에 마커를 찍은 시퀀스. Premiere에서 `File > Import`
- **타임스탬프 노트** — 방송 날짜·제목·영상 ID를 옵시디언에 기록

## 요구 사항

macOS, Python 3 (외부 패키지 없음), `brew install yt-dlp ffmpeg`

## 사용법

**다시보기** — 기본 경로입니다. 방송이 끝난 뒤 링크로 받습니다.

```sh
./archive.sh https://chzzk.naver.com/video/9330920
```

인자 없이 실행하면 링크를 물어보고, 여러 개를 넘기면 연속 처리합니다. 이미 처리된 단계는 건너뛰므로 같은 링크를 다시 실행해도 안전합니다.

**라이브 녹화** — 다시보기가 올라오지 않는 방송에 대비한 보험입니다.

```sh
./live.sh
```

`config.json`의 채널을 감시하다가 방송이 켜지면 녹화하고, 끝나면 마커까지 만든 뒤 다음 방송을 기다립니다. 한 방송만 받으려면 `--once`, 매일 정해진 시각에 자동으로 켜려면 `./live.sh schedule 20:15`.

> [!NOTE]
> **다시보기가 우선입니다.** 다음 날 다시보기가 올라왔으면 평소대로 `./archive.sh`만 실행하면 됩니다. 같은 방송의 녹화본을 알아서 갈아끼웁니다. 끝내 올라오지 않으면 녹화본이 그대로 정본이 됩니다.

## 결과물

| 위치 | 내용 |
|---|---|
| `videos/{MMDD 제목}.mp4` | 영상 |
| `premiere/{MMDD 제목}.xml` | 프리미어 마커 XML |
| `logs/{YYYY-MM-DD}/` | `all_chats.md`, `filtered_chats.md` |

옵시디언 볼트가 있으면 채팅 로그는 `치지직/로그/`, 타임스탬프는 `치지직/타임스탬프.md`에도 함께 저장됩니다.

## 설정 (config.json)

| 키 | 역할 |
|---|---|
| `live_channel_id` | `live.sh`가 감시할 채널 ID (라이브 주소 끝 32자리) |
| `highlight_users` | 닉네임에 밑줄을 표시할 유저 ID |
| `bot_users` | 로그에서 제외할 봇 계정 ID |
| `filter_messages` | 필터본에 남길 기준 문자 |
| `obsidian_vault` | 볼트 경로. 비우면 `~/Documents/Obsidian Vault` |

유저 ID는 `all_chats.md`의 닉네임 뒤 괄호 안 해시를 복사하면 됩니다.

## 동작 방식

<details>
<summary>하이라이트 검출</summary>

<br>

필터 채팅을 20초 창으로 훑어 리액션이 몰린 구간을 찾고, 몰리기 시작한 지점에 마커를 찍습니다. 기준은 방송 평균 밀도의 3배(최소 4건)라 방송마다 자동으로 맞춰집니다. 마커 간 최소 간격 80초, 최대 50개. 값은 `archive.py` 상단 상수로 조절합니다.

</details>

<details>
<summary>라이브 녹화</summary>

<br>

- **감시** — 폴링 전용 API를 30초마다 확인합니다. 하루 약 2.5MB라 상시 켜둬도 부담이 없습니다.
- **앞부분 확보** — 감지에 최대 30초가 걸리지만 플레이리스트에 남은 앞부분(약 28초)까지 함께 받아 공백을 메웁니다.
- **화질** — 1080p60을 재인코딩 없이 그대로 받습니다. 다시보기는 치지직이 오디오를 128kbps로 다시 인코딩하므로 라이브 쪽이 원본에 더 가깝습니다. 광고는 웹 플레이어가 붙이는 방식이라 파일에 섞이지 않습니다.
- **저장 형식** — 녹화 중에는 `.ts`로 받고 끝나면 mp4로 바꿉니다. mp4는 재생 인덱스를 파일 끝에 마지막으로 쓰기 때문에 중단되면 받은 분량이 통째로 안 열립니다.
- **잠자기 방지** — 도는 동안 `caffeinate`로 막습니다. 맥이 잠들면 폴링이 멈춰 방송을 놓치기 때문입니다. 화면은 꺼지게 두었지만 노트북 뚜껑은 열어두어야 합니다.
- **중단 대비** — 스트림과 채팅 모두 끊기면 재접속합니다. 여유 공간이 30GB 미만이면 시작하지 않고, 도중 5GB 아래로 내려가면 스스로 멈춰 받은 분량을 살립니다.
- **성인·구독자 전용** — 비로그인으로는 재생 정보가 내려오지 않아 받을 수 없습니다. 사유를 알린 뒤 건너뜁니다.

용량은 시간당 약 3.8GB입니다. 4시간이면 약 15GB.

</details>

<details>
<summary>같은 방송인지 판단하는 법</summary>

<br>

라이브의 `liveId`와 다시보기의 `videoNo`는 서로 다른 체계라 같은 방송이라도 번호가 다릅니다. 그래서 **방송 시작 시각**으로 대조합니다. 채팅 로그 앞머리에 남습니다.

```
---
video: 14989790
opened: 2026-09-01 20:31:17     방송 시작 시각 - 이 방송의 신원
source: vod                      live 이면 아직 다시보기가 안 올라온 방송
---
```

같은 날 방송을 두 번 했다면 시작 시각이 달라 파일명에 시각이 붙어 나뉩니다(`all_chats_2340.md`).

영상과 채팅은 항상 같은 소스에서 온 것끼리만 짝지어 씁니다. 기준 시각이 달라 섞으면 마커가 밀립니다.

</details>

## 구성

`chat.py`가 채팅(다시보기 크롤링·라이브 실시간 수집), `archive.py`가 아카이빙(다시보기 다운로드·라이브 녹화)을 맡습니다. 채팅만 필요하면 `python3 chat.py [링크]`로 단독 실행할 수 있습니다.
